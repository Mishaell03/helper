# Готовый установщик Windows одной командой

## Подготовка (один раз)

На Windows 10/11 x64 установите:

1. **Flutter SDK** со стабильного канала, поддерживающий Dart из `pubspec.yaml`.
   Добавьте `flutter\bin` в `PATH`, затем откройте новый терминал.
2. **Visual Studio 2022** (не VS Code) с компонентом **«Разработка классических
   приложений на C++ / Desktop development with C++»**, MSVC x64, Windows SDK и CMake.
3. **Inno Setup 6.3 или новее**: <https://jrsoftware.org/isdl.php>.
   Обычная установка в Program Files обнаруживается автоматически.

Проверка окружения: `flutter doctor -v`. Для загрузки Flutter-зависимостей при первой
сборке нужен интернет. Скрипт не устанавливает инструменты сам и не требует администратора.
Одного Inno Setup недостаточно: сначала нужно скомпилировать Flutter-приложение.

## Самый простой запуск

Дважды щёлкните **`build-installer.cmd` в корне проекта** или в терминале из папки
проекта выполните:

```bat
build-installer.cmd
```

В PowerShell:

```powershell
.\build-installer.cmd
```

CMD-обёртка оставляет окно открытым, чтобы можно было увидеть результат/ошибку.
Версия и номер сборки берутся из `version: 1.0.0+1` в `pubspec.yaml`.
Скрипт проверяет инструменты, получает зависимости, запускает анализатор и тесты,
собирает Flutter Windows x64 Release, добавляет распространяемые DLL Visual C++,
создаёт EXE через Inno Setup и ZIP для обновления приложения.

## Где результат

Для версии `1.0.0`:

```text
installer/output/v1.0.0/
  helper-windows-x64-setup.exe
  helper-windows-x64.zip
  SHA256SUMS.txt
```

**EXE** — готовый установщик для пользователя. **ZIP** — полный комплект программы
без внешней папки, нужен кнопке обновления. **SHA256SUMS.txt** — контрольные суммы.
Не публикуйте один `build/.../helper.exe`: без DLL и папки data он не работает.
Установщик не подписан цифровой подписью: Windows SmartScreen может показать
предупреждение неизвестного издателя. Подпись не создаётся автоматически.

Создайте GitHub Release с тегом **`v1.0.0`** и прикрепите **EXE и ZIP** из указанной
папки. Можно прикрепить также SHA256SUMS.txt. Для следующего обновления увеличьте
версию, например до `1.1.0+2`. Простое изменение `+2` не считается новой версией
для встроенного обновления. Пользовательские данные не включаются в сборку.

## Дополнительные команды

Без паузы в конце, удобно из терминала и для автоматизации:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\build_windows_installer.ps1
```

Задать версию без правки pubspec и нестандартный путь Inno Setup:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tool\build_windows_installer.ps1 -Version 1.1.0 -BuildNumber 2 -InnoCompiler "D:\Inno Setup 6\ISCC.exe"
```

`-SkipTests` пропускает анализатор/тесты, но не компиляцию. Не рекомендуется перед
публикацией. Повторная успешная сборка той же версии заменяет три файла в её папке;
старые версии остаются. Ошибка сборки не перезаписывает прошлые готовые пакеты.
Если файлы Release заняты, закройте запущенный из этой папки Helper перед сборкой.

Файл `installer/helper.iss` можно открыть в Inno Setup и нажать Compile, **после**
сборки скриптом. По умолчанию ручная компиляция ISS использует версию `1.0.0` и
выводит EXE в `installer/output`; для другой версии задайте `AppVersion`.
Рекомендуемый способ — скрипт: он синхронизирует версию EXE, установщика и ZIP.

GitHub Actions тоже использует этот скрипт при отправке тега `vX.Y.Z`.
Не публикуйте одновременно вручную и через Actions один и тот же тег.
