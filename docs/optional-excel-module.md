# Внешний модуль Excel → SQL (Windows)

Модуль необязательный: Python, DLL и GGUF **не входят** в Flutter assets или
стандартную поставку Helper. Настройка разрешает использование внешнего модуля,
а не скачивание или встраивание его в билд. Генератор Helper не собирает.

## Подключение вручную

Рядом с установленным `helper.exe` разместите **весь** готовый onedir-каталог:

```text
helper.exe
modules/
  ExcelMigrationEngine/
    generator.exe
    _internal/...
    models/qwen.gguf
```

Helper проверяет наличие модуля при запуске и каждые пять секунд.
Только при наличии EXE, каталога `_internal` и GGUF
в настройках появится «Внешний модуль Excel → SQL». По умолчанию выключен.
После включения непосредственно после «Архива» появится кнопка с таблицей.
Без файлов ни настройка, ни кнопка не показываются. Это скрытие интерфейса,
**не контроль доступа**: тот, кто располагает модулем, может его подключить.
Публичный README намеренно не рекламирует этот раздел.

Включение само по себе не запускает Python/LLM. Запуск — только по кнопке
«Создать Excel и SQL». Генератор и модель берутся исключительно из указанной
папки рядом с EXE, без поиска по PATH, запуска shell и загрузок из сети.
Устанавливайте только доверенную сборку.

## Использование

1. Скопируйте путь папки с `.xlsx` из Проводника и вставьте в поле; кавычки
   вокруг пути допустимы.
2. В «Источник SQL» выберите ввод текста или путь к локальному `.sql`-файлу.
   Вставьте SQL Server DDL (`CREATE TABLE` и поддерживаемые ограничения) либо
   укажите путь к файлу (кавычки допустимы). Файл копируется в temp побайтно,
   включая BOM/UTF-16; оригинал не изменяется. Интернет-ссылки не загружаются.
3. Выберите GPU/CUDA для подходящей внешней сборки (1650 Ti) или CPU.
   Ошибка CUDA не приводит к скрытому переходу на CPU.
4. Нажмите «Создать Excel и SQL».

JSON решений в интерфейсе нет, `--column-decisions` не передаётся.
Это не отключает проверки Python-генератора: неоднозначный план по-прежнему
блокирует выпуск результатов. Отсутствие JSON само по себе не устраняет
неразрешённые соответствия.

Последовательно выполняются два процесса с `--json-events`:
`excel-normalized` и `sql-simple`. Получаются нормализованная книга Excel
и `migration.sql`, **не C#-миграция**. Оба результата считаются готовыми только
после успешных кодов завершения и событий `completed` для обоих процессов.
Helper не исполняет SQL и не подключается к БД.

При фокусе в поле редактирования окно временно принимает клавиатурный ввод.
При уходе курсора из поля или потере фокуса оно возвращается в неактивный режим.

Входной DDL, результаты и stderr-диагностика располагаются в отдельной
системной временной папке `helper-migration-*`. Исходные Excel не копируются
и не изменяются; пути и SQL не сохраняются в настройках.
Повторная генерация удаляет предыдущую временную задачу. Кнопка «Выйти из
приложения», обновление и сброс данных также очищают её. При завершении процесса
извне, аварии или прямом нативном выходе по горячей клавише папка может остаться
в `%TEMP%`; она может содержать конфиденциальные данные.

После успешной генерации кнопка «Добавить SQL в библиотеку» импортирует весь
скрипт одним блоком в обычную библиотеку Helper. Его можно просматривать,
копировать и вводить через автоввод. Повторное нажатие для этой задачи
заблокировано. Импорт хранится в базе и не зависит от дальнейшего удаления temp.
При ошибке импорта файл SQL остаётся доступным для повторной попытки.

Переключатели «Переместить готовый Excel» и «Сохранить SQL» независимы.
Если включены перед запуском, выполняются после успешной генерации.
Уже готовое можно обработать кнопкой «Сохранить / переместить».
SQL копируется на диск; Excel **перемещается** из temp: сначала копируется,
и только после успешного копирования удаляется временный оригинал.
Входные книги не перемещаются. Перенесённый Excel не удаляется при следующем
запуске/очистке temp. Назначение внутри временной папки текущей задачи запрещено.
Пустой каталог означает настоящий рабочий стол Windows, включая перенаправление
в OneDrive. Непустое поле — каталог назначения. В нём создаётся уникальная
подпапка `ExcelMigration-*`, существующие файлы не перезаписываются.
Отмена принудительно завершает процесс; отсутствие `completed` не считается
успехом. Диагностика остаётся в temp до следующей генерации/закрытия.

## Сборка Helper

Никакого копирования из Python-репозитория в build-скриптах нет. Если вручную
положить модуль в `build/windows/x64/runner/Release/modules/ExcelMigrationEngine`,
стандартный скрипт упаковки остановится, чтобы случайно не включить Python/LLM
в installer и portable ZIP. Сначала переместите внешний модуль за пределы Release,
соберите Helper, затем подключите модуль вручную на целевом ПК.

Совместимость CUDA и реальное GPU-выполнение проверяются на целевом ПК.
