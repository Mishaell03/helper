# Обновления Windows

## Пользователь

В «Настройки → Параметры приложения» есть кнопка **«Проверить обновления»**.
Нет фоновой проверки, таймера и запросов при запуске. Основные функции по-прежнему
работают офлайн; интернет нужен только после нажатия этой кнопки и подтверждения
скачивания обновления. Используется публичный GitHub API без токена.

Проверяется последний стабильный GitHub Release репозитория `Mishaell03/helper`,
не ветка main, не коммиты и не prerelease. Сравниваются числовые major/minor/patch
с версией, встроенной в запущенную Windows-сборку. Build metadata не означает
новую версию. При отсутствии релизов, ошибке сети или лимите API выводится сообщение,
файлы приложения не меняются.

Первичная установка — `helper-windows-x64-setup.exe`. Для обновления без повторной
установки программа скачивает **соседний asset `helper-windows-x64.zip`** того же
релиза. Один произвольный EXE без ZIP недостаточен: Flutter требует также DLL и
папку data, а ключи запуска чужого установщика неизвестны.

Перед скачиванием показываются версии, размер и запрос подтверждения. Проверяются
размер архива и SHA-256 из поля `digest`, предоставленного GitHub API. Это контроль
целостности на доверии GitHub/HTTPS, не независимая подпись издателя.
Архив распаковывается и проверяется до завершения приложения: недопустимы выход
за каталог, ссылки, дубли путей, ADS и слишком большие архивы. Проверяется запись
в папку установки. Поддерживается Windows x64, Windows PowerShell 5.1, обычная
доступная пользователю папка без junction/symlink. Повышение прав не выполняется.

При установке автоматический ввод останавливается, запись скорости завершается.
Внешний PowerShell-процесс ждёт закрытия Helper, создаёт резервные копии заменяемых
файлов и копирует новую сборку, затем запускает Helper снова. При ошибке копирования
пытается восстановить заменённые файлы и удаляет только добавленные этим обновлением
файлы. При ошибке сохраняет резервную копию и `update.log` в указанной временной папке.
Откат при сбое питания/завершении самого updater или при ошибке уже запущенной новой
версии не гарантируется. Не удаляются посторонние/старые файлы в папке установки.

Импорты и скорость остаются в `%LOCALAPPDATA%\Helper`, хоткеи и параметры окна —
в HKCU. Они не включены в замену файлов. Обычное удаление через установщик тоже
не удаляет пользовательское хранилище. Прогресс печати между перезапусками не сохраняется.

## Выпуск релиза

Workflow `.github/workflows/windows-release.yml` срабатывает на тег `vX.Y.Z`.
Он проверяет проект и PowerShell-сценарий обновления на временной тестовой
установке (`tool/test_windows_updater.ps1`: замена, сохранность посторонних файлов,
откат при блокировке DLL и отказ ZIP traversal), собирает Windows x64, пакует весь Release в ZIP **без внешней
папки**, собирает Inno Setup EXE и публикует оба файла в GitHub Release.

Пример (выполняет владелец репозитория после отправки нужных изменений):

```sh
git tag v1.1.0
git push origin v1.1.0
```

Тег задаёт `--build-name`, поэтому версия EXE и релиз совпадают. Новый выпуск должен
увеличивать X/Y/Z. Обновление впервые станет доступно из сборки, уже содержащей
этот модуль. Старая версия приложения без кнопки не может обновить себя автоматически.
Для Actions нужны разрешения публикации Releases. Не публикуйте только source archives:
для встроенного обновления обязателен `helper-windows-x64.zip` с GitHub SHA-256 digest.

В macOS проверяются Dart-логика и UI. Сборку установщика и настоящий сценарий замены
занятых файлов необходимо проверить на Windows: отсутствие релиза, более старая/
равная/новая версия, отказ/подтверждение, отсутствие сети, испорченный ZIP, отказ
записи, откат при ошибке и сохранение импортов/настроек после перезапуска.
