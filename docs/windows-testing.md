# Проверка Windows 10 / Windows 11

## Миграции SQLite при обновлении

Автоматические проверки находятся в `test/markdown_migrations_test.dart`:
базы 0/1/2/3/4 с разными сочетаниями существующих колонок, сохранение ID/байтов/
настроек, повторное открытие, резервные копии, WAL, откат ошибки в upgrade и
восстановлении схемы текущей версии, отказ понижения более новой схемы и очистка
служебных копий при явном полном сбросе. Они используют отдельные тестовые базы,
а не рабочую базу пользователя. Эти проверки выполняются через SQLite FFI на
macOS; обновление установленного приложения на Windows необходимо проверить
отдельно:

1. В тестовом профиле старого Helper импортировать кириллицу/эмодзи, закрепить
   блок, создать архив, изменить скорость и описания. Закрыть приложение и
   сохранить копию всей `%LOCALAPPDATA%\Helper`.
2. Обновить всю папку приложения, не только EXE. Запустить новую сборку:
   данные и настройки должны сохраниться, схема стать 4. Рядом с базой появляется
   файл `.backup-v<старая версия>-to-v4-<время>.sqlite3`.
3. Повторно запустить: дублей колонок и новых лишних копий нет. Проверить ввод,
   архив, галочки, исходные байты и импорт нового блока с новым ID.
4. На отдельных копиях проверить неполную схему, отказ записи/нехватку места и
   файл с версией выше поддерживаемой. Ошибка не должна удалять базу или её данные;
   при неудачной миграции старая версия и содержимое сохраняются. Скопировать
   полное сообщение об ошибке для диагностики, не нажимать полный сброс.
5. Проверить восстановление из служебной копии только при закрытом Helper, по
   инструкции в `docs/markdown-helper.md`. Проверить, что явный полный сброс с
   подтверждением удаляет служебные копии, но сохраняет ручные копии пользователя.

Windows GUI/установленное обновление в текущем окружении не проверялись.

## Временная подсказка выбранного блока

Для случая Win32 8 на Windows 10 сначала проверить начальную прозрачную
поверхность без загрузки текста. Из Developer Command Prompt, каталог проекта:

```bat
cl /nologo /std:c++17 /EHsc /utf-8 /W4 /WX /wd4100 test\native\slot_notification_surface_test.cpp windows\runner\capture_exclusion.cpp user32.lib gdi32.lib /Fe:build\slot_notification_surface_test.exe /Fo:build\
build\slot_notification_surface_test.exe
```

Тест использует тот же helper инициализации, проверяет отсутствие показа/активации,
освобождение GDI-объектов и реальный результат affinity. При отказе возвращает 1,
а не объявляет успех и не показывает незащищённое окно. Это не тест захвата OBS.
**На текущем macOS этот Windows-тест не выполнялся.** Диагностика проблемного ПК
описана в `docs/capture-troubleshooting.md`, раздел про Win32 8.

Реализация добавлена, но её Windows-сборка, GUI, реестр и OBS в текущем macOS
окружении не проверены. Тесты с подменой канала не подтверждают эти свойства.

1. Собрать `flutter build windows --release`. На Windows 10 2004 (19041)+ или
   Windows 11 импортировать несколько блоков: с кириллицей, эмодзи и длинным именем.
   Проверить реальный ID из карточки, формат `ID — имя`, многоточие. Формат без
   имени — только ID; при необходимости проверить через отладочный вызов канала
   `selectedBlockChanged` с `{'id': 42, 'name': ''}`.
2. При видимом Helper менять выбор: подсказки нет. Скрыть через F12, включить
   существующий режим навигации F3 и переключать слоты. Проверить единственную
   подсказку внизу основного монитора. Быстро переключить 10 слотов: предыдущий
   текст заменяется, никаких вторых окон и наложенных номеров.
3. Переключить слот через 1 секунду: новый текст должен оставаться ещё 2 секунды,
   а не исчезнуть по старому таймеру. Проверить исчезновение без новых событий,
   немедленное скрытие при показе Helper и отсутствие подсказки при повторном
   выборе того же ID, запуске и перестроении интерфейса.
4. На светлом, тёмном и движущемся фоне проверить: видны только буквы и небольшая
   тень, нет прямоугольника, рамки, карточки или фона. Проверить читаемость.
5. Оставить курсор ввода в Блокноте. Пока подсказка видна, перетащить её за буквы;
   сразу продолжить печатать: фокус должен остаться в Блокноте, Helper не активируется.
   Удерживать мышь при перетаскивании дольше 2 секунд: подсказка остаётся до
   отпускания кнопки, затем исчезает. При отпускании раньше дедлайна остаётся
   только остаток исходных 2 секунд. Новый слот во время удержания перезапускает
   двухсекундный срок; одновременно по-прежнему существует только одно окно.
   За прозрачными участками должны нажиматься элементы другого приложения.
   Отдельного пункта подсказки на панели задач и в Alt+Tab быть не должно.
6. Снова вызвать подсказку, перезапустить приложение и повторить: позиция сохраняется.
   Перенести на второй монитор с другим масштабом (100/150/200%), изменить разрешение,
   отключить монитор. Текст должен оставаться в рабочей области, при отсутствии
   сохранённого монитора — вернуться в безопасную позицию основного.
   В тестовом профиле Windows проверить повреждённое значение
   `HKCU\Software\Helper\Window\SlotNotificationPositionV1`: приложение не падает,
   сообщает об ошибке и использует позицию по умолчанию.
7. В существующих настройках выключить «Показывать подсказку выбранного блока»:
   больше не появляется; после перезапуска выключена. Включить — действует сразу.
   Для выключения непосредственно во время показа можно вызвать существующий
   канал `setSlotNotificationEnabled(false)` из отладчика: окно сразу скрывается.
8. Записать тестовую демонстрацию OBS с захватом монитора и доступными вариантами
   Windows Graphics Capture/Desktop Duplication: отдельно проверить отсутствие
   подсказки и главной панели. Не использовать конфиденциальный текст. Защита
   Win32 не гарантирует исключение для всех сторонних способов захвата.
9. На Windows старше ограничения (сборка ниже 19041) либо в отладчике с отказом
   `SetWindowDisplayAffinity` проверить: подсказка НЕ показывается; предупреждение
   приходит через существующий канал и доступно в настройках/диагностике stderr.
   Настройки OBS и внешние процессы приложение не меняет.
10. Завершить Helper во время показа/перетаскивания: окно не остаётся, сбоев нет.
    Повторить обычные проверки F3/F6/F7/F8/F12, Esc/назад, кликов, архива,
    записи сочетаний, изменения размеров и No Activate из остальных разделов.

Переносимый тест политики (из Developer Command Prompt, каталог проекта):

```bat
cl /nologo /std:c++17 /EHsc /utf-8 /W4 /WX test\native\slot_notification_policy_test.cpp /Fe:build\slot_notification_policy_test.exe /Fo:build\slot_notification_policy_test.obj
build\slot_notification_policy_test.exe
```

Он проверяет текст, условия показа, дедлайн 2000 мс, удержание/отпускание при
перетаскивании, сброс/отмену и безопасную
геометрию. Реальную запись/чтение реестра, HWND, DPI, фокус и удаление окна
проверять вручную по шагам выше. Win32 `WM_TIMER` обрабатывается UI-потоком:
при занятом потоке скрытие может произойти позже дедлайна, но старый таймер
не может преждевременно скрыть новое уведомление. Перетаскивание не меняет
дедлайн, но откладывает скрытие до отпускания мыши. Размер шрифта уменьшен с
16 до 14 DIP, внутренний отступ — с 3 до 2 DIP, максимальная ширина — 420 DIP.

## Независимое автоскрытие интерфейса и просмотра

Windows-сборка и перечисленные нативные сценарии **не выполнялись на macOS**.
Переносимый `test/native/auto_hide_policy_test.cpp` проверяет политику на
передаваемых значениях монотонного времени, а не реальную очередь сообщений Win32.
Его можно собрать так же, как тест подсказки выше, заменив имя файла/исполняемого
файла на `auto_hide_policy_test`.

1. На тестовом профиле без `AutoHideV1` открыть параметры. Проверить включённые
   «Автоскрытие основного окна» (10 с) и «Автоскрытие просмотра текста» (30 с).
   Для каждого доступны 10, 15, …, 60 секунд и независимый выключатель.
2. Показать список и ничего не делать: через 10 секунд Helper скрывается обычным
   путём F12, остаётся запущенным. Показать снова, открыть текст: теперь 30 секунд.
   Скрытие сохраняет выбор, открытый текст, страницу и остальные состояния.
3. Через 9 секунд в списке открыть текст — получить полный срок просмотра.
   Через 29 секунд вернуться назад — получить полный срок основного интерфейса.
   Быстро скрыть/показать около старого дедлайна: новое окно не должно исчезнуть
   по предыдущему таймеру. Повторить с минимизацией и парковкой Windows 10.
4. Установить 10/45, затем выключить основной таймер, оставив просмотр включённым.
   Проверить оба режима, затем поменять их ролями. Перезапустить и проверить
   сохранение. Настройки хранятся в `HKCU\Software\Helper\Window\AutoHideV1`
   (версия, два флага и два срока); изменение применяется без перезапуска.
5. Перед истечением срока выбрать блок, прокрутить колесом/тачпадом, перейти в
   архив/закреплённые/настройки, нажать кнопку или сменить видимый слот горячей
   клавишей: отсчёт начинается заново. Пассивные перестроения/индикаторы не должны
   продлевать срок. Мышь и клавиатура в Блокноте также не продлевают срок Helper.
6. Удерживать ползунок скорости или перетаскивать/изменять размер главного окна
   дольше срока. Окно не скрывается до завершения, затем получает полный срок.
   Открыть выпадающий список длительности, подтверждение удаления, вложенный диалог,
   запись сочетания и нативный выбор файлов; оставить каждый дольше 60 секунд.
   Скрытия нет; после закрытия последнего модального окна отсчёт возобновляется.
7. Начать ввод F6, дождаться автоскрытия, проверить продолжение ввода. Повторить
   на паузе F7: пауза и позиция сохраняются, F7/F8 работают как прежде. Автоскрытие
   не должно само отправлять команды вставки, паузы, продолжения или стопа.
   Проверить F3 и освобождение предыдущего/следующего блока так же, как при F12.
8. Во всех сценариях сохраняются внешний foreground, No Activate, прозрачность
   и исключение из OBS. Отдельно повторить проверки новой двухсекундной подсказки
   выше: её таймер независим от обоих режимов главного окна.
9. «Удалить все данные приложения» возвращает настройки к включённым 10/30 с.
   При отказе записи реестра UI сообщает ошибку и не показывает несохранённое
   значение. Повреждённая настройка даёт предупреждение и безопасные значения.

Для старых изолированных сценариев `tool/test_windows_background.ps1` и
`tool/test_windows_capture.ps1`, которые намеренно оставляют окно без действий,
сначала выключить оба таймера; затем отдельно выполнить проверки автоскрытия.
Win32 `WM_TIMER` не является жёстким real-time таймером: занятый UI-поток может
обработать дедлайн позже. Таймер не опрашивает глобальную активность Windows.

## Статус

Win32-сценарии **не проверены в текущем окружении macOS**. Прохождение Dart-тестов
с подменой платформенного канала не является проверкой `RegisterHotKey`, реестра,
оболочки Windows, OBS или изменения размеров. Ниже — воспроизводимый план
проверки на реальных Windows 10 и Windows 11.

## Подготовка

1. Установить Flutter и Visual Studio с Desktop development with C++.
2. Выполнить `flutter pub get`, `flutter analyze`, `flutter test`,
   `flutter build windows --release`.
3. Запускать собранный `helper.exe` обычным пользователем в интерактивном сеансе.
   Не использовать службу или сеанс без рабочего стола. Для проверки хоткеев
   не удерживать посторонние клавиши и не использовать повышенные права.
4. В меню «Настройки приложения» нажать «Восстановить настройки по умолчанию».
   Существующие пользовательские сочетания при обновлении намеренно сохраняются;
   старое назначение F11 не заменяется автоматически.

## Автоматическая проверка на Windows

Закрыть приложение через «Выйти из приложения», затем выполнить из PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File tool/test_windows_background.ps1 -Executable build/windows/x64/runner/Release/helper.exe
```

Сценарий запускает настоящий процесс, проверяет стили HWND, отправляет клавиши
через Win32 при фокусе другого нативного окна, проверяет скрытие/показ, WM_CLOSE,
повторный запуск, выход и запуск с `--background`. В течение инициализации фонового
процесса каждые 10 мс проверяются отсутствие видимого окна и сохранение фокуса
другого приложения; повторный фоновый запуск также не должен раскрывать окно.
Не вводить текст во время
работы сценария. При неудаче он останавливает только запущенный им экземпляр.
Он не сбрасывает пользовательский реестр и не включает автозапуск.
Также проверяет отсутствие `WS_CAPTION`, совпадение клиентской и оконной областей
настоящего Helper после серии `SetWindowPos(SWP_FRAMECHANGED)` и после скрытия/показа.
Это проверка геометрии HWND, не замена ручного перетаскивания и визуального теста.

## Ручная матрица (выполнить отдельно на обеих версиях Windows)

Для чёрного фона/следа после повторного показа есть отдельный план и реальная
проверка пикселей захвата: [диагностика композиции и захвата](capture-troubleshooting.md).
Она не заменяет проверку сохранённой записи используемого рекордера.

Для зависаний открытия блока и проверки аварийного скрытия независимым потоком:
[responsiveness.md](responsiveness.md), сценарий `tool/test_windows_watchdog.ps1`.

| Проверка | Действия и ожидаемый результат |
| --- | --- |
| Русский интерфейс | Проверить заголовок, меню, настройки, кнопки, подсказки, диалог записи, сообщения ошибок и стандартные подсказки Material. |
| Показ и скрытие | Ctrl + Shift + F12 скрывает/показывает то же окно, открытый блок и состояние интерфейса сохраняются. Повторить при фокусе Блокнота и OBS. |
| Win+Tab | Перед открытием обзора задач Helper скрывается, включая фон миниатюры рабочего стола. После Esc/выбора рабочего стола сам не открывается; F12 возвращает панель. Проверить левый/правый Win, показанный/скрытый Helper, отсчёт и активный автоввод. Во время ввода Win+Tab — исключение из блокировки: ввод ставится на паузу с сохранением позиции, обзор задач открывается. Проверить именно запись обзора задач на Windows 10/11. |
| Выход | Ctrl + Shift + F4 полностью завершает helper.exe, в том числе при скрытом окне и фокусе OBS. Повторить через пункт меню. |
| Оболочка | При показанном и скрытом окне приложение отсутствует в Alt + Tab, Win + Tab и на панели задач. |
| Закрытие | X и Alt + F4 скрывают окно; процесс остаётся, F12 восстанавливает его. |
| Размеры | Тянуть все четыре края и четыре угла. Доступны размеры 360 × 300 — 1600 × 1200 логических пикселей. Интерфейс не переполняется. |
| Длительный resize | Тянуть край/угол непрерывно 15–20 секунд, затем удерживать неподвижно ещё 10 секунд и отпустить. Повторить для списка, настроек и открытого большого блока, с `--capture-diagnostics` и без него. Не должно быть аварийного скрытия, стандартной рамки/окна-призрака или нарастающих задержек; после отпускания интерфейс и хоткеи работают. В журнале — `resize.begin`/`resize.end`, без `watchdog.trip` и потока `WM_WINDOWPOSCHANGED` во время движения. Повторить тест реального зависания watchdog, чтобы подтвердить сохранение защиты. |
| Сохранение размеров | Изменить размер, скрыть/показать, затем полностью выйти и запустить заново. Размер восстановлен. Повторить при масштабировании 100%, 150%, 200% и смене монитора. |
| Смена горячих клавиш | Записать новое сочетание и нажать «Сохранить» в диалоге записи. Оно действует и сохраняется сразу, без общей кнопки. После перезапуска новое сочетание действует. Проверить Ctrl, Alt, Shift, Win, F-клавиши. |
| Обмен назначениями | Для обмена двух назначений через UI сначала выбрать временное третье сочетание: каждое отдельное сохранение проверяет запрет дублирования. Нативный API также поддерживает атомарный обмен пары без конфликта с собственными регистрациями. |
| Дублирование | Назначить одинаковые сочетания двум действиям. Сохранение отклоняется с русским сообщением, прежние назначения продолжают действовать. |
| Конфликт | В другом PowerShell выполнить команду ниже. Назначить Ctrl + Alt + F8 в приложении и сохранить. Получить русское сообщение о конфликте; прежние назначения остаются рабочими. Освободить сочетание и повторить сохранение — успешно. |
| Запись действующего сочетания | Начать запись, нажать уже зарегистрированное сочетание. В диалоге оно записывается, приложение не скрывается и не завершается. При переключении на другое приложение горячие клавиши снова выполняют действия. |
| Автозапуск | Включить «Запускать вместе с Windows». Проверить одну запись `Helper.Background` в HKCU Run с кавычками вокруг полного пути и `--background`. Выйти из Windows и войти снова — процесс запущен, окно не показано. F12 показывает его. |
| Инициализация автозапуска | Во время загрузки Flutter окно не должно мелькать или перехватывать фокус. Нажатые во время загрузки хоткеи показа/скрытия не должны отменяться завершением инициализации. Решение о первоначальном показе принимает Windows runner один раз через `finishStartup`, а не Dart через `show`. |
| Отключение автозапуска | Отключить переключатель. Удалена только собственная запись; после нового входа приложение не запускается. |
| Перемещение | При включённом автозапуске завершить приложение, переместить всю папку сборки (не только exe), вручную запустить из нового пути. Run обновлён и не дублируется. При следующем входе запускается новая копия. |
| Один экземпляр | Несколько раз запустить exe при показанном и скрытом окне — остаётся один процесс, обычный повторный запуск показывает его. Запуск с `--background` не раскрывает уже скрытое окно. |
| Фоновые ресурсы | Оставить скрытым несколько минут: нет регулярных обращений к реестру, опроса клавиш или постоянной загрузки CPU. |
| Захват экрана | Проверить пробную запись OBS; сохранён существующий WDA_EXCLUDEFROMCAPTURE. Не считать его универсальной защитой от захвата. |
| Курсор при изменении размера | В OBS с захватом курсора проверить наведение на все края/углы и перетаскивание: обычная стрелка не должна меняться на resize-курсор. Проверить отдельно Display Capture и Window Capture. |

## Навигация по слотам

### Удаление данных и компоновка параметров

В тестовом профиле импортировать блоки, закрепить и архивировать часть из них,
изменить скорость, переключатели, горячие клавиши, размер окна и позицию подсказки,
включить автозапуск. В параметрах проверить: нет логотипа/подписи Helper, скорость
над тремя последовательными переключателями. Нажать «Удалить все данные приложения»
и отменить — данные и настройки остаются. Повторить с подтверждением во время
отсчёта/ввода: ввод останавливается, повторный старт до завершения сброса запрещён.
Проверить пустые импорты, архив и закреплённые, стандартную скорость и сочетания,
включённые описания/подсказку, выключенный автозапуск, стандартные размер и позицию.
Перезапустить и повторить проверку. Исходные файлы на диске должны остаться.
При отказе доступа к реестру/SQLite не должно быть ложного сообщения об успехе;
предупреждение сообщает о незавершённом/возможном частичном сбросе. GUI, реестр
и эти нативные сценарии в текущем macOS-окружении не проверены.

### Переключение блоков

Ctrl+Shift+←/→ выбирают соседний блок в текущем порядке списка, с учётом фильтра
закреплённых, по кругу: последний → первый, первый ← последний. В открытом просмотре меняется
показываемый блок; ввод текста не запускается. В настройках меняется только выбор
блока. Во время модальных диалогов и загрузки блока навигация не выполняется.

Ctrl+Shift+F3 переключает навигацию без показа/активации окна. При обычном показе
она включена автоматически; F3 позволяет отключить её при видимом окне или
включить при скрытом. Новый цикл скрытия/показа сбрасывает ручной режим.
Отсчёт, активный ввод и пауза запрещают навигацию, в том числе через F3.
Завершение и аварийный стоп оставляют её выключенной до F3 или нового обычного
показа. Минимизация считается скрытым состоянием, а парковка Windows 10 не
считается видимостью только из-за `IsWindowVisible`.

Стрелки действительно снимаются через `UnregisterHotKey`. Если одна занята,
освобождаются обе и показывается предупреждение; после устранения конфликта
повторить F3 либо скрытие/показ. Существующие пользовательские назначения имеют
приоритет при миграции: назначенный прежнему действию F3/стрелка продолжает выполнять
это действие, а конфликтующая новая функция недоступна до переназначения.
В «Горячих клавишах» можно изменить все три действия: режим навигации,
предыдущий и следующий блок. Настройки сохраняются в `BindingsV3` (8 пар DWORD),
старые `BindingsV2`/`BindingsV1` читаются без сброса прежних назначений.

Дополнительная ручная проверка: переназначить все три действия, перезапустить
Helper и проверить новые клавиши при видимом и скрытом окне. Старые клавиши должны
освободиться; при выключенном режиме предыдущий/следующий блок не должны
перехватываться. Проверить конфликт с другим действием/приложением и сохранение
прежних назначений при отказе. На списке из трёх блоков проверить оба перехода
через край, фильтр закреплённых, открытый просмотр и единственный блок: при
неизменном ID новая подсказка не появляется. Одновременно видна только одна подсказка.

Сценарий `tool/test_windows_background.ps1` дополнительно проверяет владение
стрелками через регистрацию из другого окна: видимый/скрытый режим, F3, F6/F8,
повторный показ и откат пары при конфликте одной стрелки. Для него нужны
стандартные восемь хоткеев и свободные F3/стрелки перед запуском. Во время проверки
не вводить текст и не трогать мышь.

Отдельно вручную на Windows 10/11:

1. Импортировать три различимых блока. Оставить Блокнот foreground, показать
   Helper и переключить блоки обеими стрелками без F3. Печать остаётся в Блокноте.
2. Проверить первый/последний блок, список закреплённых и открытый просмотр.
   Выбор не запускает автоввод и не меняет foreground.
3. При видимом Helper нажать F3: стрелки выделяют слова в Блокноте. Повторный F3
   возвращает переключение блоков. Проверить много быстрых отдельных нажатий F3.
4. Скрыть Helper: стрелки доступны редактору. F3 включает скрытую навигацию без
   появления окна; второе F3 освобождает стрелки. После показа проверить выбор.
5. Нажать F6: стрелки освобождены сразу, ещё до чтения текста/конца отсчёта.
   На тестовом тексте проверить их доставку в редактор во время ввода: это ставит
   ввод на паузу, но не переключает блок Helper. Не использовать важный документ.
6. Проверить F7 (пауза/продолжение), F8 и естественное завершение: навигация не
   возобновляется. F3 во время отсчёта/ввода/паузы не резервирует стрелки; после
   стопа/завершения F3 либо новый обычный показ разрешает навигацию.
7. Повторить 20 циклов скрытия/показа, минимизацию/восстановление, Win+Tab и
   фоновый запуск; убедиться, что F3 не показывает окно и не перехватывает фокус.
8. Повторно проверить все пять прежних хоткеев, запись новых сочетаний, отмену
   записи и импорт. F3 в диалоге записи записывается, а не переключает режим.
9. Повторить No Activate, перемещение/resize и запись OBS с прежними источниками.

Новая Win32-регистрация и доставка клавиш через настоящий hook в macOS не
проверяются Flutter-тестами; эти сценарии требуют Windows.

## Клики и возврат из просмотра

На реальной Windows-сборке проверить отдельно обычные карточки, закреплённые и
блоки внутри раскрытого импортированного файла:

1. При foreground Блокнота первый одиночный левый клик сразу выделяет блок и
   не открывает текст. Второй изолированный клик по выбранному блоку тоже только
   выбирает его. Правый клик и прокрутка не открывают просмотр.
2. Два быстрых левых клика по другому, невыбранному блоку открывают именно его.
   Проверить повторное открытие после возврата и независимость кнопок меню/закрепления.
3. Стрелка «Назад» возвращает тот же список с выбранным блоком. Фильтр закреплённых
   и раскрытая группа импортированного файла сохраняются. Helper не скрывается.
4. С мышью над видимым Helper Esc закрывает просмотр даже при foreground Блокнота.
   Он временно резервируется через RegisterHotKey: в этот момент Esc не получает
   Блокнот. Увести мышь из Helper — Esc немедленно освобождается и работает в Блокноте.
5. Проверить освобождение Esc после закрытия просмотра, F12, минимизации, закрытия
   приложения, открытия модального диалога и записи хоткея. Без открытого просмотра
   Esc не резервируется. При конфликте регистрации остаётся рабочая стрелка «Назад».
6. Быстро переключить просматриваемый слот и сразу вернуться назад: поздняя загрузка
   не должна снова открыть просмотр или заблокировать список. Повторить несколько раз.
7. Проверить прежние F3/F4/F6/F7/F8/F12, автоввод, No Activate и запись OBS.
   Навигация сама не отправляет команды старт/пауза/стоп. Существующая защита
   автоввода по-прежнему может ставить ввод на паузу от любого клика мышью.

Flutter-тесты проверяют жесты и запросы регистрации, но не доказывают реальную
доставку WM_HOTKEY, отсутствие активации или результат OBS.

## Архив блоков

На Windows 10/11 после пересборки:

1. Импортировать три блока, один закрепить. Кнопкой рядом с булавкой архивировать
   невыбранный блок: просмотра/автоввода быть не должно, выбранный блок не меняется.
2. Открыть «Архив»: у вручную архивированного, ещё не введённого блока галочки
   быть не должно. Проверить двойной клик, чтение, Esc и стрелку возврата.
   После полного ввода появляется галочка; восстановление из архива сохраняет
   её и закрепление.
3. Ввести блок A полностью, выбрав во время ввода блок B: в архив должен попасть
   только A. Восстановить A и изменить скорость/открыть настройки — повторное
   состояние `completed` не должно снова отправить его в архив.
4. Повторить с F7, отменой отсчёта, F8, закрытием целевого редактора и ошибкой ввода:
   незавершённый блок не архивируется. Не использовать важные документы.
5. Перезапустить Helper, проверить архив, закрепление и исходный текст. Проверить
   обновление копии старой базы: прежние блоки изначально не архивированы.
6. В окне 360×300 проверить кнопки архива/закрепления/стопа и отсутствие переполнения.
   Проверить F3/стрелки отдельно в обычном списке и архиве: обходится текущий фильтр.
7. Проверить очистку незакреплённого (архив остаётся), затем отдельно явное удаление
   импорта/всего содержимого (архивные блоки тоже удаляются согласно подтверждению).
8. Повторить No Activate, F6/F7/F8/F12, перемещение/resize и запись OBS.

Автотесты используют настоящую SQLite, включая миграцию и ошибки записи. Состояния
Win32 в них подменены явно; они не заменяют проверку настоящего ввода и Windows GUI.

## Ограничения Windows

- Сочетания, занятые другими приложениями или зарезервированные системой,
  нельзя принудительно перехватить через `RegisterHotKey`. F12 документирован
  Microsoft как зарезервированный для отладчика. Если запрошенное сочетание
  Ctrl + Shift + F12 недоступно, приложение показывает предупреждение и предлагает
  изменить его — успешная регистрация не имитируется.
- Win-сочетания также могут быть зарезервированы оболочкой. Действия на защищённом
  рабочем столе UAC и экране блокировки не гарантируются.
- Если при фоновом запуске сохранённые сочетания заняты, ручной повторный запуск
  exe показывает существующее окно с настройками для исправления.
- Если приложение перемещено и ни разу не запущено из нового пути, старая запись
  Run сама найти его не может. Это ограничение автозапуска по абсолютному пути.
- Политики Windows и отключение автозапуска через Диспетчер задач могут помешать
  запуску независимо от наличия Run-записи.

Записать результаты, версию Windows, масштаб экрана и версию OBS перед тем,
как считать платформенную проверку завершённой.
