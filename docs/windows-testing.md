# Проверка Windows 10 / Windows 11

## Статус

Win32-сценарии **не проверены в текущем окружении macOS**. Прохождение Dart-тестов
с подменой платформенного канала не является проверкой `RegisterHotKey`, реестра,
оболочки Windows, OBS или изменения размеров. Ниже — воспроизводимый план
проверки на реальных Windows 10 и Windows 11.

## Подготовка

1. Установить Flutter и Visual Studio с Desktop development with C++.
2. Выполнить `flutter pub get`, `flutter analyze`, `flutter test`,
   `flutter build windows --release`.
3. Запускать собранный `helper.exe` обычным пользователем в интерактивном сеансе.
   Не использовать службу или сеанс без рабочего стола. Для проверки хоткеев
   не удерживать посторонние клавиши и не использовать повышенные права.
4. В меню «Настройки приложения» нажать «Восстановить настройки по умолчанию».
   Существующие пользовательские сочетания при обновлении намеренно сохраняются;
   старое назначение F11 не заменяется автоматически.

## Автоматическая проверка на Windows

Закрыть приложение через «Выйти из приложения», затем выполнить из PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File tool/test_windows_background.ps1 -Executable build/windows/x64/runner/Release/helper.exe
```

Сценарий запускает настоящий процесс, проверяет стили HWND, отправляет клавиши
через Win32 при фокусе другого нативного окна, проверяет скрытие/показ, WM_CLOSE,
повторный запуск, выход и запуск с `--background`. В течение инициализации фонового
процесса каждые 10 мс проверяются отсутствие видимого окна и сохранение фокуса
другого приложения; повторный фоновый запуск также не должен раскрывать окно.
Не вводить текст во время
работы сценария. При неудаче он останавливает только запущенный им экземпляр.
Он не сбрасывает пользовательский реестр и не включает автозапуск.

## Ручная матрица (выполнить отдельно на обеих версиях Windows)

Для чёрного фона/следа после повторного показа есть отдельный план и реальная
проверка пикселей захвата: [диагностика композиции и захвата](capture-troubleshooting.md).
Она не заменяет проверку сохранённой записи используемого рекордера.

Для зависаний открытия блока и проверки аварийного скрытия независимым потоком:
[responsiveness.md](responsiveness.md), сценарий `tool/test_windows_watchdog.ps1`.

| Проверка | Действия и ожидаемый результат |
| --- | --- |
| Русский интерфейс | Проверить заголовок, меню, настройки, кнопки, подсказки, диалог записи, сообщения ошибок и стандартные подсказки Material. |
| Показ и скрытие | Ctrl + Shift + F12 скрывает/показывает то же окно, открытый блок и состояние интерфейса сохраняются. Повторить при фокусе Блокнота и OBS. |
| Win+Tab | Перед открытием обзора задач Helper скрывается, включая фон миниатюры рабочего стола. После Esc/выбора рабочего стола сам не открывается; F12 возвращает панель. Проверить левый/правый Win, показанный/скрытый Helper, отсчёт и активный автоввод. Во время ввода Win+Tab — исключение из блокировки: ввод ставится на паузу с сохранением позиции, обзор задач открывается. Проверить именно запись обзора задач на Windows 10/11. |
| Выход | Ctrl + Shift + F4 полностью завершает helper.exe, в том числе при скрытом окне и фокусе OBS. Повторить через пункт меню. |
| Оболочка | При показанном и скрытом окне приложение отсутствует в Alt + Tab, Win + Tab и на панели задач. |
| Закрытие | X и Alt + F4 скрывают окно; процесс остаётся, F12 восстанавливает его. |
| Размеры | Тянуть все четыре края и четыре угла. Доступны размеры 360 × 300 — 1600 × 1200 логических пикселей. Интерфейс не переполняется. |
| Сохранение размеров | Изменить размер, скрыть/показать, затем полностью выйти и запустить заново. Размер восстановлен. Повторить при масштабировании 100%, 150%, 200% и смене монитора. |
| Смена горячих клавиш | Записать новое сочетание и нажать «Сохранить» в диалоге записи. Оно действует и сохраняется сразу, без общей кнопки. После перезапуска новое сочетание действует. Проверить Ctrl, Alt, Shift, Win, F-клавиши. |
| Обмен назначениями | Для обмена двух назначений через UI сначала выбрать временное третье сочетание: каждое отдельное сохранение проверяет запрет дублирования. Нативный API также поддерживает атомарный обмен пары без конфликта с собственными регистрациями. |
| Дублирование | Назначить одинаковые сочетания двум действиям. Сохранение отклоняется с русским сообщением, прежние назначения продолжают действовать. |
| Конфликт | В другом PowerShell выполнить команду ниже. Назначить Ctrl + Alt + F8 в приложении и сохранить. Получить русское сообщение о конфликте; прежние назначения остаются рабочими. Освободить сочетание и повторить сохранение — успешно. |
| Запись действующего сочетания | Начать запись, нажать уже зарегистрированное сочетание. В диалоге оно записывается, приложение не скрывается и не завершается. При переключении на другое приложение горячие клавиши снова выполняют действия. |
| Автозапуск | Включить «Запускать вместе с Windows». Проверить одну запись `Helper.Background` в HKCU Run с кавычками вокруг полного пути и `--background`. Выйти из Windows и войти снова — процесс запущен, окно не показано. F12 показывает его. |
| Инициализация автозапуска | Во время загрузки Flutter окно не должно мелькать или перехватывать фокус. Нажатые во время загрузки хоткеи показа/скрытия не должны отменяться завершением инициализации. Решение о первоначальном показе принимает Windows runner один раз через `finishStartup`, а не Dart через `show`. |
| Отключение автозапуска | Отключить переключатель. Удалена только собственная запись; после нового входа приложение не запускается. |
| Перемещение | При включённом автозапуске завершить приложение, переместить всю папку сборки (не только exe), вручную запустить из нового пути. Run обновлён и не дублируется. При следующем входе запускается новая копия. |
| Один экземпляр | Несколько раз запустить exe при показанном и скрытом окне — остаётся один процесс, обычный повторный запуск показывает его. Запуск с `--background` не раскрывает уже скрытое окно. |
| Фоновые ресурсы | Оставить скрытым несколько минут: нет регулярных обращений к реестру, опроса клавиш или постоянной загрузки CPU. |
| Захват экрана | Проверить пробную запись OBS; сохранён существующий WDA_EXCLUDEFROMCAPTURE. Не считать его универсальной защитой от захвата. |
| Курсор при изменении размера | В OBS с захватом курсора проверить наведение на все края/углы и перетаскивание: обычная стрелка не должна меняться на resize-курсор. Проверить отдельно Display Capture и Window Capture. |

```powershell
powershell -ExecutionPolicy Bypass -File tool/test_windows_background.ps1 -HoldConflict
```

## Ограничения Windows

- Сочетания, занятые другими приложениями или зарезервированные системой,
  нельзя принудительно перехватить через `RegisterHotKey`. F12 документирован
  Microsoft как зарезервированный для отладчика. Если запрошенное сочетание
  Ctrl + Shift + F12 недоступно, приложение показывает предупреждение и предлагает
  изменить его — успешная регистрация не имитируется.
- Win-сочетания также могут быть зарезервированы оболочкой. Действия на защищённом
  рабочем столе UAC и экране блокировки не гарантируются.
- Если при фоновом запуске сохранённые сочетания заняты, ручной повторный запуск
  exe показывает существующее окно с настройками для исправления.
- Если приложение перемещено и ни разу не запущено из нового пути, старая запись
  Run сама найти его не может. Это ограничение автозапуска по абсолютному пути.
- Политики Windows и отключение автозапуска через Диспетчер задач могут помешать
  запуску независимо от наличия Run-записи.

Записать результаты, версию Windows, масштаб экрана и версию OBS перед тем,
как считать платформенную проверку завершённой.
